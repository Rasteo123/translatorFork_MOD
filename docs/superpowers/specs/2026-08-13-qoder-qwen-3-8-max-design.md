# Qoder Qwen3.8-Max — дизайн

## Цель

Добавить в существующий провайдер Qoder модель `Qwen3.8-Max`, чтобы её можно было выбрать в интерфейсе переводчика и передать в Qoder Agent SDK как фиксированную модель.

Официальное название подтверждено страницей запуска Qoder: <https://docs.qoder.com/events/qwen-max>. Документация Agent SDK принимает фиксированную модель через строковый параметр `model`: <https://docs.qoder.com/cli/sdk/model-policy>.

## Изменение

В `config/api_providers.json`, в разделе `qoder.models`, появится запись `Qwen3.8-Max` со следующими параметрами:

- `id`: `Qwen3.8-Max`;
- `rpm`: `30`;
- `rpd`: `0`;
- `needs_chunking`: `true`;
- `context_length`: `200000`;
- `max_concurrent_requests`: `1`;
- `max_output_tokens`: `16384`;
- `min_thinking_budget`: `false`.

ID повторяет официальное имя модели по тому же правилу, которое уже используется для `Qwen3.7-Max`. Остальные параметры также повторяют действующую конфигурацию `Qwen3.7-Max`. Это сохраняет текущие ограничения провайдера и не требует менять обработчик `QoderApiHandler`.

## Поток данных и ошибки

После выбора модели конфигурация передаёт `Qwen3.8-Max` в `QoderApiHandler`. Обработчик устанавливает это значение в `QoderAgentOptions.model`; остальной поток запроса не меняется.

Если Qoder не разрешает модель для конкретного аккаунта или версии клиента, существующая обработка ошибок SDK продолжит возвращать `ModelNotFoundError`. Дополнительный fallback не добавляется: скрытая замена выбранной пользователем модели на другую дала бы неожиданный результат.

## Проверка

Существующий тест конфигурации Qoder будет расширен: набор ожидаемых model ID должен включать `Qwen3.8-Max`. Затем запускаются тесты обработчика Qoder и проверка корректности JSON-конфига.

## За пределами задачи

Динамическая загрузка каталога через `getAvailableModels()` остаётся отдельным улучшением. В этой задаче меняется только статический список моделей Qoder.
